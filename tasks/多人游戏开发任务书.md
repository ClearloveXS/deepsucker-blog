## 0. 现状（已确认，无需再探测）

| 项 | 值 |
|---|---|
| 框架 | **VitePress**（Vue 驱动的静态站点生成器） |
| 内容 | Markdown |
| 托管 | **Cloudflare Pages** |
| 域名 | **deepsucker.top** |
| 后端 | **无**（纯静态托管） |

### 由此锁定的架构决策

```
┌──────────────────────────────────────────────────────┐
│  前端：VitePress 静态站（Cloudflare Pages）            │
│        └─ <ClientOnly> 包裹的游戏组件                  │
│                        │                              │
│                        │ WSS                          │
│                        ▼                              │
│  后端：独立 Cloudflare Worker + Durable Objects        │
│        └─ 一个 DO 实例 = 一个游戏房间                  │
│        └─ 用 WebSocket Hibernation API（空闲不计费）    │
└──────────────────────────────────────────────────────┘
```

**⚠️ 硬约束（Cloudflare 官方规定）**：

> "You must create a Durable Object Worker and bind it to your Pages project...
> **You cannot create and deploy a Durable Object within a Pages project.**"

即：**DO 必须是独立 Worker**，Pages 只能"绑定"它，不能在 Pages 项目里直接写 DO 类。

**本方案采用「前端直连独立 Worker」而非「Pages Functions 转发」**，理由：
- 解耦，不干扰 VitePress 的构建产物结构
- Pages Functions 的 `functions/` 目录会和 VitePress 输出混在一起，容易踩坑
- 独立 Worker 可单独迭代、单独绑定自定义域名

### 已排除的方案及原因

| 排除项 | 原因 |
|---|---|
| `Taufik041/flappy-royale`（现成多人实现） | 需要常驻 Python 进程（FastAPI + uvicorn），CF Pages 纯静态跑不了 |
| 帧同步 / lockstep / 回滚 netcode | 朋友间娱乐，100ms 延迟可接受，杀鸡用牛刀 |
| 权威服务器模拟全部物理 | 本设计用「共享种子」，客户端本地生成管道，零同步成本 |
| Supabase Realtime | 免费版全项目共享 100 msg/s，4 人房 20Hz 就快打满；你已在 CF 生态，没理由绕路 |

## 1. 产品需求

### 1.1 第一个游戏：Flappy Bird 多人同屏竞速

| 需求点 | 精确定义 |
|---|---|
| 游戏类型 | Flappy Bird，横向卷轴，撞管道或地面即死亡 |
| 人数 | **最多 4 人**一局 |
| 视角 | 同一套管道，各控各的鸟，比谁活得久 / 分数高 |
| 本地 vs 远端 | **自己的鸟为「实」**（不透明、本地权威、零延迟）；**别人的鸟为「虚」**（半透明、插值渲染） |
| 游戏选择界面 | 卡片列表，每张卡有**预览图**（静态图或 GIF），点击进入 |
| 选择反馈 | 有人选了某张卡，其他人界面显示「XX 已选择」 |
| 确认流程 | 卡片下方有**确认按钮**，**所有人确认后**才开始 |
| 开始仪式 | 全员确认 → 3-2-1 倒计时 → 同步开局 |

### 1.2 硬性约束

1. 不追求竞技级同步精度，100ms 延迟可接受
2. **第一个版本不做账号系统**，输入昵称即可，localStorage 记住
3. **必须移动端可用**（触摸能玩）
4. `room` / `transport` / `presence` 三层要独立成模块，后续游戏复用
5. 后续会加更多游戏（贪吃蛇、坦克大战等），**基础设施要通用**

| `mapuya19/flappy-js` | Vite + ES6、**场景化架构**、sprite atlas | ⭐⭐⭐ 架构最好但要适配构建 |

### 2.2 选型硬指标（AI 必须逐条核对）

```
[ ] MIT 或更宽松许可
[ ] 使用 delta-time（帧率无关）      ← 硬指标，不满足就换
[ ] 无 Math.random() 生成管道 —— 或极易替换成种子随机
[ ] 物理参数（gravity/flap/pipeSpeed/gap）集中定义
[ ] 无框架、无构建步骤（或极简）
[ ] 移动端触摸可用
[ ] 代码量 < 1500 行
[ ] update / render 分离
```

> ⚠️ **delta-time 是硬指标**。若候选实现用「每帧固定位移」（`y += 5`），高刷屏上速度会翻倍，多人同步必崩。要么换，要么先改造。

## 3. 多人同步架构（核心，严格遵守）

### 3.1 共享种子 + 状态广播

```
开局：服务端生成 seed ──广播──> 所有客户端

运行中：
  [A] 本地模拟自己的鸟 ──┐
  [B] 本地模拟自己的鸟 ──┼─ 广播状态（20Hz）─> 其他人
  [C] 本地模拟自己的鸟 ──┤
  [D] 本地模拟自己的鸟 ──┘

管道：所有客户端用同一 seed + 同一 PRNG 本地生成
      → 完全一致，零同步成本
```

| 问题 | 解法 |
|---|---|
| 管道怎么同步？ | **不用同步**。开局广播 seed，各端确定性 PRNG 生成，天然一致 |
| 别人的鸟怎么显示？ | 接收远端状态 + **插值渲染**（半透明，符合"虚"的需求） |
| 带宽？ | 每人每 50ms 发 <100 字节包，4 人房 = 80 msg/s，极低 |
| 延迟感？ | 自己的鸟零延迟；别人的鸟延迟 50-150ms，视觉上是"虚"的 |

### 3.2 确定性管道生成（最容易踩的坑）

**禁止**：
```javascript
// ❌ Math.random() 各端结果不同
pipes.push({ gapY: Math.random() * 300 })

// ❌ setInterval 各端触发时机必然漂移
setInterval(() => spawnPipe(), 1500)
```

**必须**：
```javascript
// ✅ 种子 PRNG（mulberry32）
function mulberry32(seed) {
  return function() {
    seed |= 0; seed = seed + 0x6D2B79F5 | 0;
    let t = Math.imul(seed ^ seed >>> 15, 1 | seed);
    t = t + Math.imul(t ^ t >>> 7, 61 | t) ^ t;
    return ((t ^ t >>> 14) >>> 0) / 4294967296;
  }
}

// ✅ 管道由「索引」决定，不由时间决定
function pipeGapY(seed, index) {
  const rng = mulberry32(seed + index * 0x9E3779B9);
  return 80 + rng() * (canvas.height - 280);
}

// ✅ 生成由「已滚动距离」驱动，而非计时器
function updatePipes(distance) {
  const nextIndex = Math.floor(distance / PIPE_SPACING);
  while (spawnedCount <= nextIndex) {
    pipes.push(makePipe(spawnedCount));
    spawnedCount++;
  }
}
```

**验收**：开两个标签，同一 seed，逐帧截图对比管道位置必须**完全一致**。

### 3.3 网络协议

```javascript
// 客户端 → 服务端（20Hz）
{ t:'s', y:0.42, v:-3.2, s:7, a:true }
// y 必须归一化到 0-1！否则不同屏幕尺寸下别人的鸟位置错乱

// 服务端 → 客户端（广播合并）
{ t:'w', ts:1712345678901, p:[
    {id:'p1', y:0.42, v:-3.2, s:7, a:true},
    {id:'p2', y:0.61, v:2.1,  s:5, a:true},
    {id:'p3', y:0.88, v:9.0,  s:3, a:false}
]}

// 开局
{ t:'start', seed:83945213, at:1712345680000 }

// 大厅
{ t:'join',  id, name, bird:0 }
{ t:'leave', id }
{ t:'pick',  id, game:'flappy' }
{ t:'ready', id, ready:true }
```

### 3.4 渲染规则

```javascript
// 自己的鸟：本地状态，实时，不透明
drawBird(myBird.y, { alpha: 1.0, outline: '#fff' })

// 别人的鸟：插值 + 短距外推，半透明
// renderTime = now - 100ms（缓冲 100ms 换平滑）
// 两快照间线性插值；超出用 v 短距外推（不超过 200ms）
drawBird(remote.y, { alpha: 0.45, outline: playerColor })
// 死亡后画灰色坠落动画
```

## 4. 后端：Cloudflare Worker + Durable Objects

### 4.1 项目结构（独立于 VitePress 仓库，或作为子目录）

推荐**独立仓库/目录**，避免污染 VitePress 构建：

```
deepsucker-game-server/          ← 独立 Worker 项目
├── src/
│   ├── index.ts                 Worker 入口：路由 + 校验 Upgrade 头
│   └── GameRoom.ts              Durable Object：一个房间
├── wrangler.toml
├── package.json
└── tsconfig.json
```

### 4.2 wrangler.toml（关键配置）

```toml
name = "deepsucker-game-server"
main = "src/index.ts"
compatibility_date = "2024-12-01"

[[durable_objects.bindings]]
name = "GAME_ROOM"
class_name = "GameRoom"

[[migrations]]
tag = "v1"
new_sqlite_classes = ["GameRoom"]     # ⚠️ 免费版只能用 SQLite-backed
```

> ⚠️ 免费计划只能创建 **SQLite-backed** Durable Objects。用 `new_sqlite_classes`，不要用 `new_classes`。

### 4.3 Worker 入口（必须校验 Upgrade 头）

```typescript
export default {
  async fetch(request: Request, env: Env) {
    // 校验，避免为非法请求向 DO 计费
    const upgrade = request.headers.get("Upgrade");
    if (!upgrade || upgrade !== "websocket") {
      return new Response("Expected Upgrade: websocket", { status: 426 });
    }
    const url = new URL(request.url);
    const roomCode = url.searchParams.get("room") ?? "default";
    // 一个房间码 = 一个 DO 实例
    const stub = env.GAME_ROOM.getByName(roomCode.toUpperCase());
    return stub.fetch(request);
  }
}
```

### 4.4 Durable Object（必须用 Hibernation API）

```typescript
export class GameRoom extends DurableObject {
  constructor(ctx: DurableObjectState, env: Env) {
    super(ctx, env);
  }

  async fetch(request: Request) {
    const pair = new WebSocketPair();
    const [client, server] = Object.values(pair);
    // ⚠️ 关键：acceptWebSocket 而非 ws.accept()
    //    这样空闲时能休眠，不烧 duration 配额
    this.ctx.acceptWebSocket(server);
    // 跨休眠保存连接状态
    server.serializeAttachment({ id: crypto.randomUUID(), joinedAt: Date.now() });
    return new Response(null, { status: 101, webSocket: client });
  }

  async webSocketMessage(ws: WebSocket, message: string | ArrayBuffer) {
    const state = ws.deserializeAttachment();   // 休眠后恢复
    // 广播给房间内所有人
    for (const conn of this.ctx.getWebSockets()) {
      conn.send(message);
    }
  }

  async webSocketClose(ws: WebSocket, code: number, reason: string, wasClean: boolean) {
    ws.close(code, reason);
  }
}
```

**⚠️ 三个必须**：
1. 用 `this.ctx.acceptWebSocket(server)`，不是 `ws.accept()` —— 后者无法休眠
2. 用 `serializeAttachment()` 存连接状态 —— 休眠后内存会清空
3. 用 `this.ctx.getWebSockets()` 广播

### 4.7 免费额度核对

| 维度 | 免费额度 | 本设计预计消耗 |
|---|---|---|
| 请求 | 100,000 / 天 | 入站 WS 消息按 **20:1** 折算，80 msg/s × 86400 ÷ 20 ≈ 34.5 万… ⚠️ |
| Duration | 13,000 GB-s / 天（Hibernation 后不计费） | 房间空闲不计费 |
| SQLite 存储 | 5 GB | 几乎不用 |

⚠️ **请求数需要留意**：若房间长期满负荷，入站消息可能吃满 10 万/天。缓解：
- 降频到 **10Hz**（每人每 100ms 一发）→ 4 人房 40 msg/s，折算后 ≈ 17 万/天
- 或接受：个人博客的同玩频率远低于满负荷，实际很难触顶

**建议先按 10Hz 实现**（Flappy Bird 的鸟是上下运动，10Hz + 插值完全够平滑），有余量再升。

### 4.8 备选：PartyServer（封装更好，但生态在迁移中）

```bash
npm install partyserver partysocket
```

- 底层就是 Durable Objects，走同样的 CF 计价
- 封装了 room 概念，开发体验更好
- ⚠️ 老的 `partykit` npm 包（0.0.115）自 2025-05 起停更，**新项目用 `partyserver` + `partysocket`**（仓库 `cloudflare/partykit`）

**本方案选裸 DO**，理由：逻辑极简（就是个房间广播），少一层抽象少一层坑，且 Cloudflare 官方文档对 DO WebSocket 支持完善。若 AI 实现时觉得繁琐，可切 PartyServer。

## 5. 前端：VitePress 集成（SSR 是最大坑）

### 5.1 ⚠️ VitePress 会在 Node.js 里预渲染，构建时没有 window/document

**这是本技术栈最容易翻车的地方**。以下写法会导致 `vitepress build` 直接失败：

```javascript
// ❌ 构建时崩溃：window is not defined
const width = window.innerWidth
const saved = localStorage.getItem('name')
const canvas = document.getElementById('game')
```

### 5.2 三种正确写法（按推荐顺序）

**方式 1：`<ClientOnly>` 包裹（最简单，推荐给游戏组件）**

```vue
<!-- docs/games/flappy.md 中可直接使用 -->
<ClientOnly>
  <FlappyGame />
</ClientOnly>
```

`<ClientOnly>` 在 SSR 阶段渲染空内容，mounted 后才渲染真实内容。

**方式 2：`defineClientComponent`（组件导入时就访问浏览器 API）**

```vue
<script setup>
import { defineClientComponent } from 'vitepress'
const FlappyGame = defineClientComponent(() => {
  return import('../components/FlappyGame.vue')
})
</script>

<template>
  <FlappyGame />
</template>
```

**方式 3：`onMounted` 里访问（局部逻辑）**

```vue
<script setup>
import { ref, onMounted } from 'vue'
const roomCode = ref('')

onMounted(() => {
  // ✅ 这里安全
  const params = new URLSearchParams(window.location.search)
  roomCode.value = params.get('room') ?? ''
  const savedName = localStorage.getItem('playerName') ?? ''
})
</script>
```

**也可用 `import.meta.env.SSR` 或 `inBrowser` 判断**：
```javascript
import { inBrowser } from 'vitepress'
if (inBrowser) { /* 安全 */ }
if (!import.meta.env.SSR) { /* 安全 */ }
```

### 5.3 页面路由

VitePress 是文件路由，直接建 md 文件：

```
docs/
├── games/
│   ├── index.md        → /games         游戏大厅（卡片列表）
│   └── flappy.md       → /games/flappy  游戏房间
└── .vitepress/
    ├── config.mts
    └── theme/
        ├── index.ts
        └── components/
            ├── GameLobby.vue        卡片大厅（ClientOnly）
            └── FlappyGame.vue       游戏主体（ClientOnly）
```

**房间码用 URL query**：`/games/flappy?room=KX7P`
在 `onMounted` 里用 `window.location.search` 读取（VitePress 的 `useRoute()` 对 query 支持不直观，直接读 location 更稳）。

### 5.4 主题注册

```typescript
// .vitepress/theme/index.ts
import DefaultTheme from 'vitepress/theme'
import GameLobby from './components/GameLobby.vue'
import FlappyGame from './components/FlappyGame.vue'
import type { Theme } from 'vitepress'

export default {
  extends: DefaultTheme,
  enhanceApp({ app }) {
    app.component('GameLobby', GameLobby)
    app.component('FlappyGame', FlappyGame)
  }
} satisfies Theme
```

### 5.5 可复用模块

```
.vitepress/theme/multiplayer/
├── transport.js     WebSocket 封装：连接、重连（指数退避）、心跳
├── room.js          房间逻辑：创建/加入/离开、座位管理、房主
├── presence.js      在线状态：谁在、谁确认了、昵称与颜色
├── sync.js          状态广播与插值：发送节流、快照缓冲、插值助手
└── prng.js          确定性随机：mulberry32
```

⚠️ 这些模块若**在 import 时就访问浏览器 API**，必须用 `defineClientComponent` 动态导入，否则构建失败。建议写成纯函数/类，不在模块顶层碰 window。

## 6. 房间 / 大厅系统

### 6.1 流程

```
/games                     卡片列表（预览图 + 标题 + 在线人数）
  └─ 点击 → /games/flappy?room=XXXX
      无 room 参数 → 自动生成新房间码

/games/flappy?room=XXXX
  ├─ 4 个座位（昵称 + 颜色 + 确认状态）
  ├─ 玩法说明
  ├─ 「我准备好了」按钮
  └─ 全员 ready → 3-2-1 → 广播 start+seed → 开始
```

### 6.2 房间码

- 4 位大写字母（如 `KX7P`），**不含易混淆字符 O/0/I/1**
- 复制邀请链接按钮
- 房间无人后 5 分钟自动销毁（DO 可用 `ctx.storage.setAlarm`）

### 6.3 断线处理

```
玩家掉线：座位保留 30s，显示「重连中…」
30s 未重连：座位释放，其鸟判定死亡
房主（第一个进来的）掉线：房主顺延
全员掉线：房间销毁
```

## 9. 常见坑与规避

| 坑 | 后果 | 规避 |
|---|---|---|
| 在 VitePress 里直接 `window.xxx` | **构建直接失败** | `<ClientOnly>` / `defineClientComponent` / `onMounted` |
| 想在 Pages 项目里直接写 DO 类 | 不支持，部署失败 | DO 必须独立 Worker，Pages 只绑定 |
| 用 `ws.accept()` 而非 `ctx.acceptWebSocket()` | 无法休眠，烧光 duration 配额 | 用 Hibernation API |
| 用 `new_classes` 而非 `new_sqlite_classes` | 免费版创建失败 | 免费版只能 SQLite-backed |
| `Math.random()` 生成管道 | 各端不一致，游戏崩溃 | 种子 PRNG，加 ESLint 规则全局禁用 |
| `setInterval` 生成管道 | 各端节奏漂移 | 改为按滚动距离索引 |
| 发送绝对像素坐标 | 不同屏幕位置错乱 | 归一化到 0-1 |
| 高刷屏（120Hz）速度翻倍 | 物理不同步 | delta-time + 固定步长累加器 |
| 不做插值直接跳 | 别人的鸟一卡一卡 | 100ms 渲染缓冲 + 线性插值 |
| 忘记 HTTPS | 本地能跑上线就挂 | 生产必须 WSS |
| 20Hz 广播吃满请求配额 | 超出免费额度 | 先按 10Hz 实现 |
| 前端连 workers.dev 遇跨域 | 连接失败 | 绑定 `game.deepsucker.top` 同源 |

## 11. 开发中实际遇到的问题（2026-09 AI 执行记录）

> 以下坑是本地 `wrangler dev`（workerd 4.x / wrangler 4.130）实测踩出来的，任务书正文没写到的部分。

| # | 问题 | 症状 | 解法 |
|---|---|---|---|
| 1 | **DO 类必须从入口文件 `export`** | 只 `import { GameRoom } from './GameRoom'` 不 re-export，启动报 `GameRoom is not exported in your entrypoint file` | `src/index.ts` 里 `export { GameRoom }` |
| 2 | **新版 workerd 里 `DurableObject` 不再是全局变量** | `class GameRoom extends DurableObject` 在模块求值时 `ReferenceError: DurableObject is not defined` | `import { DurableObject } from 'cloudflare:workers'` |
| 3 | **新版 workerd 的 alarm 回调参数是对象不是时间戳** | `webSocketAlarm(timestamp)` 收到的是 `AlarmInvocationInfo {scheduledTime, retryCount, isRetry}`，`timestamp >= startAt` 对象比较恒 false，倒计时永远不触发 | `const ts = typeof info === 'number' ? info : info.scheduledTime` |
| 4 | **wrangler dev 不热重载** | 改了 TS 没生效，反复排查半天 | 每次改完重启 dev（本地用 `setsid` 后台 + 杀端口重启脚本） |
| 5 | **npm allow-scripts 机制** | `npm install` 后 esbuild 二进制没链接，tsc/vite 报 `esbuild: command failed` | `npm approve-scripts esbuild workerd` |
| 6 | **multiplayer 模块要能被纯 Node 无头测试** | 模块内 `import './prng'`（无扩展名）在 Node ESM 下解析失败 | 所有内部 import 带 `.js` 扩展名（Vite 两种都兼容）；模块顶层不碰 `window`，测试时桩掉 `localStorage/sessionStorage` |
| 7 | **玩家身份放 sessionStorage 而非 localStorage** | 同机多标签测试时两标签共享同一 id，服务端当成重连互相踢座位 | `sessionStorage['ds-game-id']`：每标签页一个身份，刷新=新身份，旧连接关闭后服务端释放座位 |
| 8 | **VitePress build 日志带 ANSI 色码** | `grep "ReferenceError\|error"` 可能因色码错位漏匹配 | 验证时看完整 tail 输出，不只信 grep |
